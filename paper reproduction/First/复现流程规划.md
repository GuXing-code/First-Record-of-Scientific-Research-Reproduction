1. **先把论文目标说清楚**
   目标不是“完全一模一样数值”，而是复现算法链路：DFE、PTR-DFE、PTR-SIC-DFE、ATR-DFE，并看到论文同样的性能趋势。
2. **先搭一个最小工程**
   建这些文件：
   run_main.m（总入口）
   default_config.m（所有参数）
   qpsk_mod.m / qpsk_demod.m / calc_ber.m
   先让 run_main.m 能跑完并打印“开始/结束”。
3. **先做“无信道”通信闭环**
   只做：随机比特 -> QPSK -> QPSK解调 -> BER。
   目标：BER 接近 0。
   这是你后面所有算法的地基。
4. **加入信道和噪声（先单用户）**
   实现：多径卷积 + AWGN。
   这时 BER 会升高，说明“信道损伤”出现了。
5. **实现 DFE（RLS）**
   把接收信号送入 DFE，训练段用已知符号，后续判决反馈。
   目标：DFE后 BER < DFE前 BER。
6. **实现 LS 信道估计**
   用训练序列估计信道。
   先单用户验证估计是否基本合理（看冲激响应和主径位置）。
7. **实现 PTR**
   按估计信道做时反匹配合并。
   然后接 DFE，得到 PTR-DFE。
   目标：PTR-DFE 性能优于仅 DFE（至少趋势更好）。
8. **扩展到双用户“同步”场景**
   两个用户同时到达接收端，产生多址干扰。
   先跑 PTR-DFE，你会看到 BER 变差，这是正常现象。
9. **实现 SIC**
   按论文流程做：
   解码顺序 -> 干扰估计 -> 对齐 -> 缩放 -> 相减 -> 再解码 -> 迭代。
   得到 PTR-SIC-DFE。
   目标：迭代次数增加时 BER 下降并趋于稳定。
10. **实现 ATR**
    在频域求自适应权重（MVDR思路），再回时域合并，后接 DFE。
    得到 ATR-DFE。
11. **做“同步场景”对比实验**
    同一参数下比较：PTR-DFE、PTR-SIC-DFE、ATR-DFE。
    输出 BER 曲线（随 SNR 变化）。
12. **做“异步场景”**
    设置用户到达时延不同，截取重叠部分按同步方法处理。
    同样比较三种方法性能。
13. **固定参数并整理结果**
    把你最终参数写进 default_config.m：阵元数、比特数、训练长度、DFE抽头、RLS参数、迭代次数、SNR范围等。
    保证每次运行结果可复现（固定随机种子）。
14. **最后写复现说明**
    README 写三件事：
    怎么运行、每个算法模块在哪里、你复现到了什么程度（仿真链路/无外场数据）。
